# Glossary

| Term | Meaning |
|---|---|
| **AS IS** | Today’s process, as it actually is |
| **Control data** | Reports, logs and check results that arise along the way. Small filled circles in the phase colours |
| **Data state** | An agreed, stable state in which data are stored on the target platform. In this edition: source data, input data, processed data, statistics and output data, tagged SD, ID, PD, ST and OD |
| **Data type** | What kind of data a data set is: metadata, micro data, macro data, statistics or output data. Shown in the core of the data symbol |
| **Dependency** | A process takes data from, or delivers data to, another statistic, a register or an external party. Drawn with a dashed grey line in 3.0 |
| **Detail (level 3)** | A drawing of what happens inside one system |
| **Focus (level 2)** | A drawing of one process step with all its systems and data sets |
| **Framework system** | A system developed by other units, where the producing unit cannot change the code. With menu: the unit can adapt some of it |
| **Gate** | A checkpoint in the mapping process: a draft before the workshop (gate 1), and confirmation by the owners before anything goes further (gate 2) |
| **GSBPM** | Generic Statistical Business Process Model, the international reference model for statistical production. Dataflow uses phases 4–7 |
| **Legacy platform** | A platform that is to be retired, for example SAS, FAME or Oracle in the worked example |
| **Lens** | A version of the overview that highlights what one decision needs, for example platform and deadline |
| **Merge** | Several elements go on to the same element |
| **Model** | The description of a process as data (YAML in 3.0, Excel in 2.0). The drawings are made from it |
| **Output data** | Disseminated statistics that are openly available. Drawn with petals |
| **Overview (level 1)** | A drawing of the whole process as 5–10 process steps |
| **Phase** | One of the four GSBPM phases that Dataflow uses: collect, process, analyse and disseminate |
| **Platform** | The system or tool a step runs on, for example SAS, FAME, Excel or the target platform |
| **Process step** | A group of systems and data sets that together do one thing, which can be described in one sentence |
| **Quality checklist** | A list of what is interpreted or not confirmed, divided by who must confirm it |
| **Skill** | A set of instructions that teaches an AI assistant a working method. *dataflow* is the skill for this framework |
| **Source tag** | Where a field in the model comes from: D1, D2, D3, 2.0, workshop or interpretation |
| **Split** | One element goes on to several elements |
| **System with bespoke code** | A system the producing unit developed itself and can change |
| **Target platform** | The platform production is moving to, often a cloud data platform |
| **TO BE** | The target state, as the process is to be on the target platform |
